先想清楚：贪吃蛇是怎么“动”的

贪吃蛇看起来是在“动”，其实没有任何东西真的滑过去了。 它在每一刻都只是把整条蛇重新画一遍，一般每秒画 10 次。 上一秒的蛇在这里，下一秒的蛇就朝前挪了一格 —— 你的眼睛就把这串静止的画面看成了动画。 2013 年的诺基亚手机游戏和 1976 年的街机，都是同一个道理。

所以这个游戏的核心，其实只有三个动作，每秒重复 10 次：

  1. 算（update）：算出蛇下一秒应该在哪 —— 那一格有没有食物？撞墙了没有？咬到自己了没有？
  2. 画（draw）：把整块画布清空，再按最新位置画一遍蛇和食物。
  3. 等一小会儿，再回到第一步。

这三件事按顺序、不停重复，有一个专门的名字：game loop（游戏循环）。

小故事 · 让浏览器“下次再画”的那一招

很早以前，网页要做动画，得靠 setInterval（每隔一会儿执行一次）。 问题是：它不看屏幕上现在有没有画面，就算你切到别的标签页、或者电脑卡了一下，它也照样按时“叫醒”你，于是动画就一顿一顿的。

2011 年前后，浏览器厂商合力推出一个更聪明的函数： requestAnimationFrame，直译“请求动画帧”。 它的意思是：“等浏览器下次准备好重画屏幕时，请顺便执行我的函数。” 这样游戏循环就和屏幕刷新率对上了，动画变得很顺滑，切到后台时还会自动慢下来，省电。

这个函数一出来，网页游戏的大门就打开了。今天你在浏览器里玩的游戏，几乎都靠它驱动。

小故事 · 那个被抄了无数遍的 <canvas>

“画布”（canvas）其实在 2004 年前后就在浏览器里悄悄出现了。 据说苹果公司当时想在网页里画图，就往浏览器里加了一个 <canvas> 标签。 这个标签背后没有复杂的插件，只提供一块“空白纸”和一支“刷子”。

因为简单，它很快成了网页游戏的标准画布：贪吃蛇、俄罗斯方块、小蜜蜂，全都画在上面。 今天你看的很多网页图表、小游戏，也都是用 <canvas> 画出来的。

第 2 步 · 让方块一格一格往前走

STEP 2用变量表示“位置”step2.html

现在方块固定在 (10, 10)。想让它动，就要把“它在哪”变成一个能改的数字。 这个“能改的盒子”，在 JavaScript 里叫 变量（variable）。 

const 每格 = 20;   // 一格 20 像素
let 列 = 10;       // 第几列（横着数）
let 行 = 8;        // 第几行（竖着数）

// 让列往右走一格
列 = 列 + 1;

// 画的时候：像素 = 格数 × 20
pen.fillRect(列 * 每格, 行 * 每格, 每格, 每格);

只是把“列”加 1，画面并不会自己变。画布是一张静态的纸： 上次画在 (10,8) 的方块还留在原地。所以想要“动”，必须先清空，再画新的。

完整代码：

<script>
  const board = document.getElementById("board");
  const pen = board.getContext("2d");

  const CELL = 20;      // CELL = 格子，每格 20 像素
  let col = 10;         // col = column，列
  let row = 8;          // row，行

  function draw() {
    // 先擦掉整块画布
    pen.clearRect(0, 0, board.width, board.height);

    // 再画新的位置
    pen.fillStyle = "#ff6b6b";
    pen.fillRect(col * CELL, row * CELL, CELL, CELL);
  }

  draw();
</script>

let 和 const 的区别 要改的用 let，不会改的用 const。如果对 const 的变量重新赋值，浏览器会直接报错。 养成“能 const 就 const”的习惯，以后改代码会少很多意外。
小故事 · 为它改过两次名字的这个词

“变量”（variable）这个词，最早来自数学家：它指的是“可以变的那种量”，比如 x、y。 1970 年前后，C 语言为它造了 int 这样的类型。 后来 JavaScript 借鉴了别的语言里的 var（variable 的缩写），但它有个有名的毛病：变量声明会被“偷偷提到”函数开头，很容易出错。

2015 年，JavaScript 大改版（ES6），一下子加进来 let 和 const 两个新词。 “let” 本意是“让 …… 发生”，写起来像一句英语：let speed = 150; —— 让速度等于 150。今天的代码里，几乎看不到 var 了。

第 3 步 · 加一条尾巴，变成蛇

STEP 3一串小方块排队step3.html

一条蛇，其实就是一串有顺序的坐标。第一个是头，后面的都是身体。 在 JavaScript 里，这种“一串东西”叫 数组（array），用方括号 [ ] 写出来。 

// 蛇：[ {列, 行}, {列, 行}, ... ]
const snake = [
  { col: 10, row: 8 },   // 头在这里
  { col: 9,  row: 8 },   // 身体
  { col: 8,  row: 8 },   // 尾巴
];

// 画蛇：对蛇里的每一节，都画一个方块
snake.forEach(function (part, index) {
  // 头用亮一点的颜色，身体用暗一点的
  pen.fillStyle = index === 0 ? "#4ade80" : "#22c55e";
  pen.fillRect(part.col * CELL, part.row * CELL, CELL, CELL);
});

常见坑 · 数组序号从 0 开始 snake[0] 是第一个（头），snake[1] 是第二个。 不要从 1 数起，几乎所有编程语言都从 0 开始。
小故事 · 为什么从 0 数起

这个习惯可以追到 1960 年代的 C 语言（甚至是更早的机器码）。 当时内存里的每个位置本来就有编号，第一个位置的地址就是 "起始地址 + 0"。 如果第一项叫 "1"，那每次取第 n 项就得算 "起始地址 + (n - 1) × 每项大小"，白白多一步减法。

于是 C 语言直接让下标从 0 开始 —— 后来的 Java、Python、JavaScript 全继承了这个习惯。 今天的程序早就不在乎那一次减法了，但这个约定留了下来。

第 4 步 · 让蛇听键盘的话

STEP 4键盘事件step4.html

键盘的每一次按下，浏览器都会报告一个事件（event）。 想“听”这些事件，就要加一个监听器（listener）。 

// 方向表：按键名 → 方向
const DIRECTIONS = {
  ArrowUp:    { col:  0, row: -1 },
  ArrowDown:  { col:  0, row:  1 },
  ArrowLeft:  { col: -1, row:  0 },
  ArrowRight: { col:  1, row:  0 },
};

let direction = { ...DIRECTIONS.ArrowRight };   // 一开始向右走

document.addEventListener("keydown", function (event) {
  // event.key 就是按下的那个键的名字
  const key = event.key;

  if (DIRECTIONS[key]) {
    direction = { ...DIRECTIONS[key] };
  }
});

逐句翻译：

  • document.addEventListener("keydown", ...)：给整个文档加一个监听器，专门听 keydown（按键按下）这个事件。
  • event.key：这次按下的键，方向键分别是 "ArrowUp" / "ArrowDown" / "ArrowLeft" / "ArrowRight"。
  • if (DIRECTIONS[key])：如果这个键在方向表里，就切换方向；如果按的不是方向键（比如字母 x），就什么也不做。
event事件n.
listener监听者（监听器）n.
add添加v.
keydown按键按下n.
Arrow箭头n.
direction方向n.
spread展开（三个点 ... 符号的名字）v.
... 那三个点是什么？ { ...DIRECTIONS.ArrowRight } 的意思是“把那个对象的属性抄一份出来”。 不能直接写 direction = DIRECTIONS.ArrowRight，因为那样两个名字会指向同一个对象，改一个另一个也会跟着变。 这里其实不太会出错（我们从不修改方向对象），但抄一份是好习惯，第 11 步你会看到它的用处。
小故事 · “监听器”这个比喻

“事件监听”这个说法，来自一个真实生活中的类比：大家围坐在屋子里，谁发生了什么事，就“报”一声，其他人都能听到。 浏览器里发生的每一件小事 —— 鼠标点了、键盘按了、窗口大小变了 —— 都会“报”一声。

早期的浏览器里，这件事叫 onclick（“在……上点”），只能挂一个。 后来大家发现一个页面上可能有很多东西关心同一个事件，于是有了 addEventListener（添加事件监听者）： 可以挂很多个，互不打扰，还可以用 removeEventListener（移除监听者）摘下来。

第 5 步 · 自动跑起来

STEP 5让蛇自己往前走、撞墙停下step5.html

现在蛇能在按键后挪一格，但不会自己跑。到这一步，游戏循环正式登场。

let speed = 150;       // 每 150 毫秒走一格
let lastMove = 0;      // 上一次“走”的时间

function move() {
  const head = snake[0];
  const next = {
    col: head.col + direction.col,
    row: head.row + direction.row,
  };

  // 把新头插到最前面，把旧尾巴去掉
  snake.unshift(next);
  snake.pop();
  // 注意：这里先不加食物！到第 8 步再说。
}

function loop(now) {
  // 看看现在距离上次走，够不够一个 speed
  if (now - lastMove >= speed) {
    move();
    lastMove = now;
    draw();
  }
  requestAnimationFrame(loop);   // 告诉浏览器：下次再叫我
}

requestAnimationFrame(loop);

push压入（在“最后”加一个）v.
shift把“第一个”拿出来v.

tail尾巴n.
next下一个adj.

新头的“出生”，和旧尾巴的“死亡” 先 unshift（在头前面插一格）→ 再 pop（把尾巴那一格扔掉）。 蛇的长度不变，看起来就是“往前爬了一格”。 到第 8 步加食物时，你只要在 pop 前面 判断一下“这格有食物吗”，有就不 pop。
常见坑 · now 是个什么数 requestAnimationFrame(loop) 会自动把“从打开页面到现在的毫秒数”作为参数传给 loop。 这个数很大（几十万、几百万），所以一开始要设 lastMove = 0，它会立刻跑一次，你就能马上看到画面。
小故事 · 1976 年，贪吃蛇本来叫“封锁”

第一只“贪吃蛇”出现在 1976 年，是一款街机游戏，名字叫 Blockade（封锁）。 玩法很简单：屏幕上用箭头控制一条线，走过的地方会留下痕迹，谁先撞到任何东西谁就输。

后来这个玩法被一次次“改造”（很多开发者没有申请专利），慢慢变成了今天的样子：撞墙要死，撞到自己要死，吃到食物会变长 —— 就像我们今天玩的这样。1998 年，诺基亚手机把它装进了 3310，取名叫 “Snake”，从那以后，它就成了全世界很多人人生中的第一个游戏。

所以你现在玩的这个版本，其实已经比 1976 年那一版“进化”了很多。

注意：第 5 步里撞墙先不处理 蛇会“走出画面”，因为画布外面没有东西可画，看起来就是消失了。 别急，第 6 步来处理。

第 6 步 · 撞墙了怎么办

STEP 6用“状态”决定游戏是否结束step6.html

游戏需要一个“它现在在干什么”的标记。我们叫它 status（状态）。 状态的取值只有几种："playing"（玩着）、"over"（结束了）。 

const BOARD_SIZE = 24;           // 24 行、24 列（480 ÷ 20 = 24）
let status = "playing";

function update() {
  const head = snake[0];
  const next = {
    col: head.col + direction.col,
    row: head.row + direction.row,
  };

  // 撞墙检测：有没有超出 0 ~ 23 的范围？
  if (
    next.col < 0 || next.col >= BOARD_SIZE ||
    next.row < 0 || next.row >= BOARD_SIZE
  ) {
    status = "over";
    return;                       // 结束，不再往下走
  }

  snake.unshift(next);
  snake.pop();
}

小故事 · 游戏开发者的“状态机”

在游戏行业里，“游戏有几种状态、状态之间怎么切换”，有一个专门的词叫 finite state machine（有限状态机）。 这个名字还很新，但想法在早期程序里就有：比如电梯有“上楼、下楼、停住”三种状态，从“上楼”切到“停住”要按开门。

到今天，几乎所有游戏 —— 包括你手机里那些大制作 —— 都是这样： 开始页 → 游戏中 → 暂停 → 游戏结束。你的贪吃蛇，状态是 "playing" 和 "over" 两个；如果加上暂停，就是三个。

第 7 步 · 加上食物

STEP 7随机位置的食物step7.html

食物的位置每次都是随机的。生成随机数要用 Math.random()（Math = 数学，random = 随机）：

let food = { col: 5, row: 5 };

function placeFood() {
  // Math.random() 给出 0 到 1 之间的小数
  // × 24 后是 0 到 23.99……，Math.floor 向下取整 → 0 到 23 的整数
  food = {
    col: Math.floor(Math.random() * BOARD_SIZE),
    row: Math.floor(Math.random() * BOARD_SIZE),
  };
}
random随机的adj.
Math数学n.
floor地板（向下取整）n./v.
round四舍五入v.
ceil天花板（向上取整）n.
place放置v.
position位置n.

Math.floor（向下取整）和 Math.round（四舍五入）很容易混。 想想它们的名字：floor 是地板，往下掉；ceil 是 ceiling（天花板），往上顶。

小故事 · 为什么是“伪”随机

计算机其实不会“随机”。你给 Math.random 要一个数，它内部其实是在一个很长的公式上往前走一步， 算出看起来毫无规律数，但只要你拿到起点，就能算出后面每一个数。所以这种随机叫 伪随机（pseudo-random）。

为什么不用真的？因为便宜 —— 伪随机数算得飞快，而且大多数游戏、抽奖、加密之外的地方，根本分不出差别。 （安全相关的随机，比如生成密钥，就不用这个了。）

STEP 8吃到就变长，然后放新的食物step8.html

第 11 步 · 补上“缓冲方向”这个小坑

STEP 11那个“按太快会自杀”的问题step11.html

回到第 4 步。我们的代码是“一按键，马上改方向”。这看起来没问题，但有一个很多老教程都没讲的坑：

坑 · 按得太快会“自杀” 蛇正在向右走（每秒 10 步）。

你在同一秒里先按 ↑，再按 ←。

第一下：方向变成“上”，但蛇还没机会走一步；
第二下：方向又变成“左”。
于是蛇的下一步直接往左，撞进了自己的身体 —— 你明明没有按错，却死了。
小故事 · 那个让我抓狂的 180 度转身

很多贪吃蛇教程都会加一句：“不能按和当前方向相反的方向”。比如往右走时，按左键就忽略。

但光有这一句是不够的：它只防住了“立刻掉头”，防不住“按两下、拐错弯”。 我当年就是在一分钟里连死了三次，才开始怀疑代码。后来想明白了： 问题不在“哪个方向不能按”，而在于“方向改得太早了”。

解决办法：加一个“方向缓冲”

按方向键时，不直接改方向，而是先把它记在一个“等待表”里（叫 nextDirection，下一个方向）。 等蛇真的走了一步之后，才把等待表里的方向“装”上去。 

let direction = { col: 1, row: 0 };      // 现在走的方向
let nextDirection = { col: 1, row: 0 };  // 下一次要走的方向

document.addEventListener("keydown", function (event) {
  const wanted = DIRECTIONS[event.key];
  if (!wanted) return;

  // 规则：新方向不能和“上一步已经走过的方向”相反，也不能和它一样
  const isOpposite =
    wanted.col === -direction.col && wanted.row === -direction.row;
  const isSame =
    wanted.col === direction.col && wanted.row === direction.row;

  if (!isOpposite && !isSame) {
    nextDirection = wanted;   // 先记下来，等走一步再装
  }
});

function update() {
  direction = nextDirection;   // 走一步之前，先把等待的方向装上
  ...
}

这里的 wanted（想要的方向）、isOpposite（是否相反）、isSame（是否相同）都是我自己起的名字。 起得越像英语句子，以后越好读。

为什么这件事值得单独讲 好的游戏，光“能跑”还不够，还要“手感对”。 你以后会不断遇到这种问题：规则没错，但玩起来不对劲。这时候就去拆解： 是哪一毫秒你的意图被丢了？从那里下手。
小故事 · “手感”是个专业词：game feel

游戏设计师把“按键与角色反应之间那一点点微妙的感觉”叫 game feel（游戏手感）。 它没有标准答案，但有很多真经验：跳跃时按住越久跳得越高、被击中时屏幕抖一下、吃食物时闪一下 —— 这些都不是游戏规则的一部分，却决定了你玩得爽不爽。

你做的贪吃蛇里，也可以加一点：吃食物时格子弹一下，结束时画面抖一下。这些都要等你做完基础版再慢慢加。

小故事 · 那个让网页能“自己干活”的函数

JavaScript 诞生于 1995 年。当时网景（Netscape）公司想让网页能响应用户操作，找来了 Brendan Eich（布兰登·艾克）， 他用了大约 10 天就写出了第一版原型，最初叫 Mocha（摩卡），后来改成 LiveScript，最后为了让市场更接受， 改名成 JavaScript。

名字里带 Java，其实和当时热门的 Java 语言关系不大，更多是为了借它的名气。 但这个“顺手”起出来的名字，让人们以为它只是给网页加点小特效的玩具。 十几年后，跑到浏览器里的东西越来越多，才有人认真对待它。 今天你玩的这个贪吃蛇，用的就是它。
